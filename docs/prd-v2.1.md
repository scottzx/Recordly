# Recordly v2.1 产品需求与交互设计稿

> 状态：设计草案，供产品与开发评审；文中新增命令、界面和数据结构均为拟议能力。
> 目标产品版本：2.1.0；可先发布 2.1.0-beta.1。编写日期：2026-09-24。
> 本文只定义版本，不表示功能已经实现；不修改当前应用版本号。

## 1. 版本主张

**把口播与屏幕讲解素材，变成可以按文稿剪辑、审阅 AI 修改、继续精修的视频工程。**

v2.1 的主线：

**录制／导入 → 转写文稿 → 提出删减建议 → 试听与采纳 → 精修 → 导出。**

目标用户：制作软件教程、产品演示、知识讲解和单人口播的创作者。优先服务已有录屏、人像和讲解音频的工作流。

本版本解决三个问题：

1. 素材进入软件后，难以快速辨认、选择并开始剪辑。
2. 用户理解的是句子和内容，却必须主要通过时间线完成粗剪。
3. Agent 能修改工程，但用户缺少检查修改原因、试听结果和选择性采纳的完整界面。

产品验收案例：一位用户导入 15 分钟的口播＋录屏，生成文稿，试听并采纳重复表达／长停顿建议，得到能继续调整字幕、镜头和 B-roll 的工程，导出与预览一致的 MP4。15 分钟是验收素材规格，不是处理耗时承诺。

## 2. 现有基础与事实边界

基于当前工作区源码阅读，未在本次文档任务中运行完整产品验收。安装包状态可能与源码不同。

| 模块 | 当前基础 | v2.1 要补的能力 |
| --- | --- | --- |
| 素材库 | 导入视频、预览、多选建工程、拖入时间线 | 真实缩略图、时长、状态、筛选、已使用标记 |
| 工程 | v4 素材实例、多个同步来源、镜头编排、B-roll、包装幕 | 文稿与具体素材实例关联、粗剪审阅元数据 |
| 字幕 | Whisper／TranscribeKit、停顿辅助断句、字幕修改 | 全文文稿、跨素材转写、句子对应声画的剪辑 |
| CLI/MCP | 录制、标记、render、project inspect/apply/validate/preview | 素材查询与建工程、转写、建议导入、审阅与应用 |
| 自动化 | 编辑计划 v1，GUI 与 CLI 使用共享编排规则 | 带基础版本校验的候选修改；统一效果时间映射 |
| GUI | 素材／设置侧栏、预览、时间线、保存与撤销 | 文稿工作区、修改审阅、未保存时的外部更新处理 |
| 预设与包装 | 外观预设、片头／章节／观点／片尾／图片卡 | 本版本沿用；整套栏目模板与叠加动效后续推进 |

重要区别：现有静音分析服务于字幕断句，不等于已有“自动剪除停顿”；已有 CLI 不等于已有完整口播 Skill；已有素材库也不等于语义素材检索。

## 4. 用户旅程

### 4.1 从一条口播开始

1. 首页选择“剪辑口播”，导入视频，生成工程。
2. 进入文稿页；显示“生成文稿”，说明所用本地转写引擎。
3. 选择讲解音轨，生成文稿；有唯一可用音轨时自动选中，有多个候选时让用户选择并试听。
4. 文稿生成后，可直接按句粗剪，或点击“检查长停顿”。
5. 希望处理重复和重录时，使用“交给 AI 助手”复制该工程的工作流指令；Agent 生成建议文件，用户导入审阅。
6. 审阅页展示原句、原因、原片试听和删减后试听。用户采纳／忽略，最后应用已采纳项。
7. 回到编辑器调整镜头、字幕和 B-roll，保存并导出。

### 4.2 从录屏＋人像开始

1. “录制讲解”复用现有录制配置、权限与录制器。
2. 录制结束后进入对应素材的编辑器，突出“生成文稿”。
3. 文稿删除针对整组主讲片段：同步录屏、人像和主讲声音一同裁剪，保持同步。
4. 操作标记、缩放、字幕和标注按相同内容移动；可继续用现有镜头布局精修。

### 4.3 从多个素材开始

1. “组合素材”进入素材多选，显示选择序号，可调整顺序后创建工程。
2. 每个素材选择自己的讲解来源；文稿按成片顺序连接，保留素材分隔和来源名称。
3. 同一素材使用两次时显示两个文稿实例；删除其中一处不影响另一处。
4. 不含音频的素材保留在时间线，文稿显示“无讲解音频”，不生成虚构文字。

## 5. 前端信息架构与交互

### 5.1 首页与素材库（F01、F02）

保留“素材库／剪辑项目”结构，上方新增三张场景入口卡。不要为三个入口创建三套工程模型。

素材卡包括：缩略图、可编辑显示名称、时长、录屏／视频标记、摄像头标记、就绪状态。名称修改只改索引，不改源文件名。项目内素材库显示“已使用 N 次”。

- 普通点击预览，复选框选素材，拖动或“插入播放头”进入工程。
- 筛选首版提供“全部／录制／导入”；名称搜索即时生效。
- 缩略图取媒体有效范围内的代表帧；失败显示占位与重试，不阻止可用素材插入。
- `processing` 显示当前处理步骤；源文件丢失显示“重新定位”；格式无法解码显示原因。
- 重新定位需验证素材身份；内容不同的文件按替换素材处理，使相关转写和建议失效。
- 全局素材库 P0 沿用视频／录制导入；图片和独立音频继续走已有编辑器入口，不扩大为全媒体资产平台。

### 5.2 编辑器布局

在现有 EditorShell 上渐进调整：左侧增加“文稿”和“修改审阅”，保留素材与设置入口，中央继续使用共享预览，下方保留时间线。

目标逻辑分区如下；P0 可让属性与左侧工作区切换，P1 再拆成独立右侧面板。

```text
工程名称    已保存／未保存    撤销／重做                     导出
────────────────────────────────────────────────────────────
素材 / 文稿 / 修改审阅  │          视频预览          │ 属性（可收起）
                       │                           │
句子与时间             │ 原片 / 修改后试听          │ 当前选中对象
删减建议与原因         │ 播放与音量                 │ 的设置
────────────────────────────────────────────────────────────
主讲与镜头 / 来源 / B-roll / 字幕 / 标注 / 配乐时间线
```

P0 在 1280×800 窗口下可完成所有核心操作；窄窗口隐藏非必要属性区，不能靠页面横向滚动找到“应用”按钮。不在无选中对象时保留大块空属性区。

### 5.3 文稿工作区（F03、F04）

顶部：搜索、生成／重新生成、讲解来源选择、“检查长停顿”、“交给 AI 助手”。

正文：按成片顺序列出句子，展示成片时间和素材分隔；播放时高亮当前句。来源时码放在详情中，避免同时显示两套难辨认的时间。

- 点击句子：跳转到成片对应位置并选中；播放操作由播放按钮或空格触发。
- Shift 点击：选择连续句子；“从视频中删去”生成候选修改，支持试听后应用。
- P0 以整句为最小文字剪辑单位，不承诺逐字切割。句子跨已有切点时，按可见片段分别定位。
- “修改文字”只修改当前实例的文稿显示／绑定字幕，不修改音视频。生成字幕前的文字校对保留到字幕生成结果。
- “从视频中删去”修改声画，按钮带剪刀图标并显示预计减少的时长。
- 被删句在本轮审阅中显示删除线；导出的文稿和字幕只包含当前有效内容。
- 改文稿后已有语义建议标记过期；重新转写创建新 transcript revision，保留旧版本用于历史解释，不静默替换正在审阅的引用。
- “生成字幕”复用现有样式。首次生成全部句子；再次生成优先更新绑定字幕，保留人工样式和独立手工字幕，不能无提示清空现有字幕。

### 5.4 修改审阅（F05）

摘要示例：“8 条建议；已采纳 3 条；预计缩短 00:42”。示例数字不构成质量承诺。

每条建议展示：原文或停顿位置、来源时间、原因、建议类型、受影响内容、原片试听／修改后试听、采纳／忽略。

状态：`pending → accepted / rejected`；应用前可任意改选；引用失效时进入 `stale`。所有建议初始为 pending，不默认勾选语义删减。

- P0 允许 `remove-range` 一类编辑意图；停顿缩短表现为删除停顿中间的一段。
- 重复／重录建议必须包含删去句与保留句的引用；不能只写“AI 认为不重要”。
- 停顿由真实音频静音区间产生，不能只用字幕之间的空隙推断。
- 原片试听播放切点前后各约 1.5 秒；修改后试听从候选工程播放同一上下文。
- 每次选择变化都从同一基础工程重建候选；时长按实际合并后的删除区间计算，避免重复扣减。
- 相互重叠的建议标记为冲突组，P0 不允许同时采纳，避免原因和恢复状态不一致。
- “应用已采纳项”作为一个撤销事务；未采纳项不改变工程。应用后本轮审阅封存。
- “撤销本轮应用”只能在对应撤销栈位置执行。之后经过其他精修，需要先撤销后续步骤；P0 不实现跨历史的任意单项恢复。
- 已应用后再次剪辑开始新一轮审阅，基于最新工程生成；历史记录可查看原因，但不再次执行。

### 5.5 错误、任务与外部更新

任务状态统一为 idle、running、succeeded、failed、cancelled；界面显示真实处理阶段和可重试范围，无进度数据时不用假百分比。

| 情况 | 用户可见行为 |
| --- | --- |
| 转写运行时／模型缺失 | 引导配置或下载；手工剪辑仍可用 |
| 无可识别语音 | 显示“未识别到语音”，保留素材和时间线 |
| 某一个来源转写失败 | 标记该来源失败，可单独重试；其余已完成文稿可读 |
| 取消转写 | 终止本轮子进程，保留完整成功缓存，不写半份文稿 |
| 建议引用失效 | 标记过期并阻止应用，提示基于当前工程重新生成 |
| GUI 有未保存修改且磁盘工程改变 | 保留当前编辑；提示查看外部版本或另存当前版本，不自动覆盖 |
| GUI 无未保存修改且磁盘工程改变 | 显示可重新载入提示；播放中延后处理，避免突然跳转 |
| 导出失败 | 保留工程及已采纳结果，提供错误和重试 |

现有外部文件监听会触发工程载入；v2.1 必须在载入前补充未保存修改与当前播放状态检查。

## 6. 本地服务与处理规则

这里的“后端”指 Electron 主进程、Node CLI 与共享处理逻辑，P0 不新增服务器。

### 6.1 职责划分

| 层 | 责任 | 不承担 |
| --- | --- | --- |
| 外部 Agent / Skill | 理解内容、发现重复／重录、提出有引用的建议 | 直接覆写当前 GUI 工程 |
| 共享领域逻辑 | 时间映射、建议验证、候选编译、效果联动 | UI、模型调用 |
| 本地媒体服务 | 探测、缩略图、音频提取、转写、静音分析、缓存 | 决定内容是否应删除 |
| Electron IPC | 授权路径与桌面任务生命周期、文件选择 | 另写一份剪辑算法 |
| CLI / MCP | 非交互输入、结构化输出、调用相同服务 | 绕过建议和工程验证 |
| React | 文稿、审阅、预览、保存、撤销 | 用文字索引自行推导声画切点 |

现有转写模块依赖 Electron 的 app、运行时路径和录制会话。应提取必要的引擎执行核心，通过参数注入 ffmpeg、模型、临时目录和进度回调；桌面与 CLI 各自提供适配层。不另造第二套 Whisper 实现。

### 6.2 时间、来源与实例

- 所有新接口使用毫秒和半开区间 `[startMs, endMs)`；不混用秒和帧号。
- 转写以实际音频素材源时钟保存，不能绑定一条会随剪辑移动的成片时间线。
- 必须通过 `sourceClips` 的入点、偏移、速度，将语音区间映射到主讲段落和成片。不能只使用旧工程的单一 videoPath。
- 文稿显示引用同时包含 transcript revision、segment ID、素材实例 ID 和当前片段 ID。
- 同一录制重复插入时是不同 instance；一次删除只作用于当前选择的实例。
- 每个素材实例显式选一个讲解音频来源。P0 不自动混合多个说话者来源，不自动判断机位里的声音是否相同。
- 音频来源独立调整后仍按其实际 sourceClips 映射；无法映射、跨越缺失来源的建议须标记不支持，不能猜时间。

### 6.3 粗剪与声音、效果

候选编译器把源引用转换为基础工程上的确定区间，再通过共享 split／trim／remove 规则执行；按稳定顺序处理，不能用执行后已位移的时码继续删除。

| 对象 | 删除主讲区间后的规则 |
| --- | --- |
| 同步录屏／人像／主讲声音 | 整组裁剪并闭合间隙，源文件不变 |
| 镜头编排、关联 B-roll | 按交集裁剪并保留内容对应位置 |
| 字幕、缩放、标注 | 调用统一时间映射，裁剪／移动到相同内容；孤立片段移除 |
| 独立 BGM / audioRegions | 沿用成片时间定位，P0 不自动压低或按句重排；超出尾部按现有导出规则裁掉 |
| 独立包装幕 | 文稿剪辑不删除；在保留内容之间维持顺序 |

审阅中提示存在独立配乐时需试听新切点；不要为了粗剪新增整套音频编排模型。字幕仅有句级时码时不做虚假的字级精度承诺，切点应提供人工微调入口。

### 6.4 长停顿建议

复用现有 ffmpeg 静音检测能力。草案默认：连续静音至少 1,500ms 才建议，保留总计至少 500ms 的停顿（两侧各 250ms）。数值需通过内部验收素材试听后冻结，不复用字幕分段 padding 当剪辑参数。

只在选定主讲来源的有效区间内处理；头尾静音独立标记；所有范围钳制到真实媒体时长。即使规则命中，也只产生建议，不自动剪掉用户的停顿。

### 6.5 基础版本、原子写入与重试

- `baseRevision` 为工程规范化持久化编辑状态的 SHA-256，排除保存时间、缩略图缓存、审阅选择和派生状态；包含媒体引用、时间线、效果、声音及文稿校对。
- 文件内容变化另用素材指纹校验。P0 指纹至少覆盖规范化路径、大小、mtime；疑似替换时使缓存失效。该指纹不宣称内容级去重能力。
- GUI 从当前内存快照创建审阅；CLI 从磁盘快照创建。应用前重新校验当前快照与素材指纹。
- 不一致则返回 `STALE_BASE` 或 `MEDIA_CHANGED`，不自动合并。刷新建议比误剪更可控。
- GUI 应用候选产生一个内存撤销事务，仍由保存动作持久化。CLI 始终输出新工程，拒绝覆盖输入及已有输出。
- 临时文件完整写入并验证后再原子落位；失败不留下看似成功的目标工程。
- Review apply 不就地修改基础工程；相同基础、建议和选择产生相同编辑状态。时间戳等报告元数据不参与确定性比较。
- 同一审阅禁止重复导入应用到其衍生工程；应用记录使用 review ID 与选择摘要标识。

## 7. 数据契约草案

### 7.1 版本区分

应用版本是 **2.1.0**；现有工程已经使用 v4；现有 EditPlan 为 v1。三者不能混为一谈。

建议包含文稿／审阅元数据的新工程采用 **工程 v5**，实现前验证旧版对未知版本的行为，并以新文件保存和保留原文件保证可回退。新应用继续读 v1–v4；旧格式只在首次保存新格式时迁移。普通旧工程的画面与声音不能因迁移改变。

保留 EditPlan v1 作为原有底层操作协议；新增独立 ReviewPlan v1，不把内容理解信息塞进所有旧操作。旧 CLI 调用保持原行为。

### 7.2 素材索引与转写

素材索引新增可选字段：`origin: recording|imported`、`durationMs`、`width/height`、`thumbnailPath`、`fingerprint`、`analysisStatus`、`error`。现有 ready/processing 与新增分析状态分离，缩略图失败不把能剪辑的视频降为不可用。

TranscriptDocument v1 包含：

| 字段 | 含义 |
| --- | --- |
| id / revision / schemaVersion | 文稿身份、不可变内容版本、协议版本 |
| assetId / sourceId / fingerprint | 实际语音来源与媒体身份 |
| engine / model / language / optionsHash | 缓存判定所需的转写配置 |
| segments[] | 稳定 id、sourceStartMs、sourceEndMs、text；可选真实 word timing |
| silenceIntervals[] | 有限有效媒体范围内的检测区间 |

缓存按来源指纹＋引擎／模型／语言／参数命中，重复插入素材不重复转写。工程嵌入使用到的文稿和实例校对，不依赖全局缓存才能重开；原音视频仍按现有路径引用，v2.1 不承诺工程素材打包。

### 7.3 ReviewPlan v1 示例

以下为协议形状示例；id、哈希与时间均为占位值，不能直接用于实际工程。

```json
{
  "schemaVersion": 1,
  "id": "review-001",
  "baseRevision": "sha256:BASE_REVISION",
  "producer": { "kind": "agent", "name": "recordly-oralcut" },
  "suggestions": [
    {
      "id": "suggestion-001",
      "kind": "retake",
      "reason": "本句重新开始，下一句表达完整；建议保留下一句。",
      "action": "remove-range",
      "target": {
        "instanceId": "instance-A",
        "clipId": "clip-A",
        "sourceId": "audio-A",
        "transcriptId": "transcript-A",
        "transcriptRevision": "revision-1",
        "segmentIds": ["segment-12"],
        "sourceStartMs": 12300,
        "sourceEndMs": 15800
      },
      "evidence": {
        "keepSegmentIds": ["segment-13"]
      }
    }
  ]
}
```

`kind` P0 允许 `pause / repetition / retake / manual`。跨来源的保留句证据须使用完整引用，简写 keepSegmentIds 只适用于与 target 相同的文稿版本。pause 可以没有 segmentIds，但必须对应检测到的静音范围；manual 可以只对应精确源区间。

审阅文件包含不可变基础工程快照、ReviewPlan、选择状态与校验信息。GUI 当前未保存工程也能据此审阅；CLI 将其保存为 `.recordly-review.json`。外部建议文件只有 ReviewPlan，不自带可执行脚本。

校验拒绝：不存在的 ID、非法／非有限时间、越界、媒体身份变化、基础版本不匹配、缺失原因、语义建议没有可核对证据、冲突项同时采纳。拒绝整个应用事务，不静默丢弃错误项后执行其余部分。

## 8. CLI 设计

以下命令是 v2.1 拟新增接口，不代表当前可运行。

### 8.1 命令清单

| 命令 | 输入与输出 | 说明 |
| --- | --- | --- |
| `library list --json` | 素材元信息与状态 | 返回稳定 library ID |
| `library import <file> --json` | 新／已有素材 ID | 复用素材登记与探测；不复制源视频 |
| `project create --media <id> ... -o <file>` | 素材 ID 列表 → 工程 | 按参数顺序组装；可创建空工程 |
| `transcript generate <project> --sources <file> -o <file> --json` | 来源选择映射 → 文稿集合 | sources 文件把各素材实例映射到讲解 source ID；唯一来源可省略 |
| `transcript export <file> --format markdown -o <file>` | 文稿集合 → 带引用的可读文稿 | 供人或 Agent 阅读；保留句 ID 和来源时码 |
| `review create <project> --transcript <file> --suggestions <file> -o <file>` | 基础工程＋文稿＋建议 → 审阅文件 | 导入 Agent 建议，验证所有引用 |
| `review create <project> --transcript <file> --pauses -o <file>` | 文稿静音数据 → 审阅文件 | 本地规则，无 LLM；与 suggestions 互斥 |
| `review inspect <review> --json` | 审阅文件 → 建议、冲突、预计时长 | 不改变工程 |
| `review apply <review> --project <base> --selection <file> -o <new-project>` | 明确选择 → 新工程＋应用报告 | 与当前 base 校验；原子执行 |
| `review apply ... --dry-run --json` | 相同输入 → 影响报告 | 校验并在内存编译，不写工程，无需 -o |

selection 文件形状：`{"schemaVersion":1,"acceptedIds":["suggestion-001"]}`。未列入的建议不应用；未知或重复 ID 直接报错。没有 acceptedIds 时合法返回无变化报告，不生成假成功剪辑。

`transcript generate` 的输出包括工程 baseRevision、来源映射和各 TranscriptDocument。部分来源失败时也写有明确 complete=false 的诊断产物并返回非零退出码；review create P0 要求完整成功的文稿集合，避免半份文稿被误当完整内容处理。

### 8.2 闭环示例

```bash
# 以下为拟议 v2.1 接口；素材 ID 由 library import/list 返回。
recordly library import talk.mp4 --json
recordly project create --media MEDIA_ID -o talk.recordly
recordly transcript generate talk.recordly -o talk.transcript.json --json
recordly transcript export talk.transcript.json --format markdown -o talk.transcript.md

# Agent 阅读文稿，按 ReviewPlan v1 写 suggestions.json。
recordly review create talk.recordly --transcript talk.transcript.json --suggestions suggestions.json -o talk.recordly-review.json
recordly review inspect talk.recordly-review.json --json
recordly review apply talk.recordly-review.json --project talk.recordly --selection selection.json --dry-run --json
recordly review apply talk.recordly-review.json --project talk.recordly --selection selection.json -o talk.roughcut.recordly --json

# 沿用已有接口；v2.1 需验证其支持新工程数据。
recordly project validate talk.roughcut.recordly
recordly project preview talk.roughcut.recordly --from 3000 --to 8000 -o excerpt.mp4
recordly render talk.roughcut.recordly -o talk.mp4 --json
```

### 8.3 输出、取消与兼容

- 新命令 `--json` 的 stdout 只输出一个结果对象：`{ok,data,error,warnings}`；进度进入 stderr，MCP 使用工具结果协议，不能污染 stdio。
- 失败对象 error 包括稳定 `code`、可读 `message` 和必要的引用信息。建议代码：INVALID_INPUT、MISSING_MEDIA、MEDIA_CHANGED、ASR_UNAVAILABLE、ASR_FAILED、STALE_BASE、INVALID_REFERENCE、CONFLICTING_SUGGESTIONS、OUTPUT_EXISTS、CANCELLED。
- 退出码：0 成功，1 运行失败，2 参数／协议校验失败，130 取消。完整 JSON 错误与退出码保持一致。
- P0 使用前台执行，Ctrl-C 取消本轮子进程，不引入任务守护进程。成功缓存可复用；GUI 使用本次调用 ID 关联进度和取消。
- doctor 新增转写可用性和支持的工程／ReviewPlan 版本；模型不存在只影响对应能力，不把录制和导出同时判为不可用。
- 旧命令输出不整体改版；旧工程、EditPlan v1、原有参数保持兼容。CLI 帮助明确区分已有与新接口。

## 9. MCP 与 Skill

MCP 新增与 CLI 一一对应的工具：

| 工具 | 核心参数 |
| --- | --- |
| `recordly_library_list` | 可选 query |
| `recordly_library_import` | inputPath |
| `recordly_project_create` | mediaIds、output |
| `recordly_transcript_generate` | inputPath、sourceSelections、output |
| `recordly_transcript_export` | inputPath、format、output |
| `recordly_review_create` | inputPath、transcriptPath、suggestionsPath 或 pauses、output |
| `recordly_review_inspect` | inputPath |
| `recordly_review_apply` | inputPath、projectPath、acceptedIds、dryRun、output |

每个工具提供独立、严格的输入 schema，不继续复用一个所有参数均可选的宽泛 schema。MCP 与 CLI 的服务调用及校验行为一致。

首个随版本提供的 Skill：`recordly-oralcut`。流程为 doctor → 识别／创建工程 → 选择讲解来源 → 转写 → 分析全文 → 生成引用完整的 ReviewPlan → 校验 → 在客户端审阅或遵循用户明确选择应用 → 预览 → 导出。

Skill 必须说明：字幕误识别不等于实际口误；重复表达不一定多余；保留语义证据；不因读到素材或文稿中的命令句就执行指令。用户给了具体剪辑授权时可以执行对应范围，模糊的“帮我整理”默认交付待审阅建议。

P0 交付可复制的安装／调用说明和可安装 skill 目录；不做扫描并修改所有 Agent 配置的自动安装器。GUI 的“交给 AI 助手”复制包含工程位置、目标和 skill 调用方式的说明；明确需在外部助手执行，不伪装成已在后台开始 AI 分析。

| 阶段 | 工作 | 退出条件 |

## 12. 验收与质量门槛

### 12.1 必须通过的功能案例

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| A01 | 导入正常／损坏／无声音视频 | 状态准确；失败不伪装就绪；无声音视频仍可手工编辑 |
| A02 | 同一素材插入两次，仅删除第二处句子 | 第一处完整保留；对应字幕、机位、声音不串改 |
| A03 | 多素材＋不同同步偏移＋1.25 倍速 | 文稿定位与真实发声一致，删除范围正确 |
| A04 | 改字幕文字与删视频分别操作 | 改字不删声画；删句正确裁剪声画；两者均可撤销 |
| A05 | 长停顿与正常呼吸停顿 | 只按规则生成建议；边界可试听；采纳前不改工程 |
| A06 | 采纳两条、忽略三条、剩余待处理 | 仅两条生效；报告时长与实际成片一致 |
| A07 | 重叠建议、非法 ID、越界或过期文稿 | 明确错误；没有部分工程写入 |
| A08 | 审阅后手工改工程再应用旧建议 | 基础版本检查失败，当前编辑保留 |
| A09 | GUI 未保存时外部程序改工程 | 不静默覆盖；可查看外部版本或另存当前版本 |
| A10 | 中断转写／重试／重新打开 | 无半成品成功状态；完整缓存可复用；旧工程可打开 |
| A11 | 含 B-roll、包装、字幕、缩放、标注和配乐的工程删句 | 各对象遵守第 6.3 节规则；预览与导出一致 |
| A12 | GUI 与 CLI 应用相同基础和选择 | 持久化编辑状态等价；时长及导出声画一致 |
| A13 | v1–v4 工程迁移、v5 保存重开 | 原工程保留，迁移前后画面声音一致，文稿／审阅数据不丢 |
| A14 | 安装版无开发 Node 环境 | CLI 转写、审阅、预览、导出可运行；缺模型有明确诊断 |

### 12.2 自动化与人工验证

- 领域测试覆盖时间投影、重复实例、偏移、变速、切点边界、B-roll／字幕／标注联动、候选确定性、原子失败。
- 集成测试以固定转写夹具验证 GUI／CLI／MCP 一致性，避免把模型随机差异误判为剪辑回归。
- 实际转写测试使用带音频的固定验收素材，验证引擎适配和取消；真实口播再人工试听误删与截字。
- 延续 composition-export 和 library-export 的真实媒体验证；不能只检查 JSON 成功字段。
- 人工验收覆盖 1280×800、较大桌面窗口、键盘操作、焦点与播放快捷键冲突、撤销重做、保存重开。
- macOS 是新增完整流程的首发验收平台。Windows／Linux 维护现有功能回归，新能力按引擎和平台支持状态明确展示，未经验证不宣称全平台功能等价。

性能目标为待基准验证的验收目标：本地缓存下 200 条素材可渐进显示且不等待全部探测；1,000 句文稿搜索／选中反馈 p95 ≤ 200ms；100 条建议选择后摘要更新 p95 ≤ 300ms。测试时记录设备、素材规模和冷／热缓存；转写耗时独立记录，不写未经测量的“极速”承诺。

### 12.3 产品验证

用同一组代表素材对比现版和 v2.1：完成初剪耗时、手工拖时间线次数、建议采纳与恢复次数、成功保存重开及导出的比例。建议采纳率用于观察，不鼓励通过减少建议或默认勾选制造高指标。

首轮建议用 5 条已知内容的口播／录屏样本，分别覆盖重录、长停顿、多素材、同步人像、已有 B-roll。无不可恢复工程损坏、无素材实例误删、无未保存覆盖，作为发布硬门槛。语义效果由人工逐条核对，不能仅以“模型返回成功”验收。

## 13. 草案中的产品决策

当前推荐决策如下，开发可据此拆任务；更改时应同步本文范围和验收标准。

1. v2.1 核心是口播与屏幕讲解的文稿粗剪，不把通用 AI 视频生产全链路塞进本次发布。
2. P0 采用外部 Agent 提建议、本地客户端审阅的架构；本地无模型账号也能完成基础闭环。
3. 优先整体句子和明确停顿剪辑，逐字精剪与跨历史任意恢复后续做。
4. P0 复用现有侧栏完成文稿／审阅，不把全编辑器布局重做设为发布前置。
5. 项目格式建议升级 v5，产品版本升级 2.1.0；不提前更改源码版本号和 Release 记录。
6. B-roll 智能匹配、栏目模板、工程打包和外部剪辑器导出后续独立评估。

实施前 M0 必须冻结：讲解来源映射的确切 schema、v5 旧版行为、工程 revision 规范化字段列表、停顿参数试听结果。上述是待技术验证项，不应伪装成现有能力。
